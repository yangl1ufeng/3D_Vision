# Gemini 2 真机采集进度

**实时画面：** 双击 `start_gemini2_viewer.cmd`。窗口左侧是彩色画面，右侧是与彩色画面对齐的深度伪彩色图，黑色表示无有效深度；右侧显示有效像素比例。按 Q 或 Esc 关闭。此窗口只预览，不自动保存，随时可用 `start_gemini2_capture.cmd` 采集一帧保存。

**点云导出：** 双击 `start_gemini2_pointcloud.cmd`，从最新保存的深度图生成 PLY 点云；实测记录和模拟器接入路线见 [真实场景重建](REAL_SCENE_SIMULATION.md)。

**多帧静态建模：** 双击 `start_gemini2_static.cmd`，固定相机和桌面后采集 20 帧并融合成一份深度快照，再导出 PLY 点云。采集期间应关闭实时预览窗口，避免相机资源冲突。结果只是可见表面；桌面世界坐标和物体碰撞形状还需标定和拟合。

2026-11-12：Windows 已识别 Orbbec Gemini 2 的彩色、深度、红外和数据接口，状态均为 OK。D 盘 `.venv-vision` 已安装官方 `pyorbbecsdk2` 2.1.3。`probe_gemini2.py` 用官方 SDK 同时开启 RGB 与深度流，软件对齐深度到彩色画面；连续检查至多 60 帧，保存有效深度最多的一帧及相机参数。

双击 `start_gemini2_capture.cmd` 重新采集。结果保存在 `runs/gemini2_probe/<时间>/`：`rgb.png`、米制 `depth_m.npy`、`valid_mask.npy` 和 `report.json`。只在本机 D 盘保存；采集完成后立即关闭相机流。拍摄时请把桌面与一个不反光的待抓物体放在画面中央。

首次单帧画面 `20261112_151335_629462`：RGB 与对齐深度均为 1920×1080，只有 2.3% 有效深度，画面几乎全白。随后连续采集的 `20261112_151513_581095`：60 帧中保存的最好一帧有 83.7% 有效深度，RGB 过曝像素约 0.9%。两次的彩色与对齐深度内参一致，SDK 深度比例为 1 mm/单位，实际中位深度第二次约 3.63 m。第二次画面主要是天花板与显示器，桌面并未成为主要区域，因此暂不能用于桌面目标抓取评估。

用户调整镜头后再采得 `20261112_151752_095359`：56 帧中保存的一帧有效深度占 79.7%，过曝约 0.17%，有效深度的中位数约 0.50 m。画面已包含桌面，左下有外置设备，前方有手机，但桌面上也有笔记本电脑。报告保存了彩色和对齐深度的内参、畸变模型及参数；对齐深度配置报告零畸变，彩色相机报告 `BROWN_CONRADY_K6` 畸变，后续几何处理不能略过这一差异。

按画面粗框计算的局部深度覆盖率：手机约 53%，左侧外置设备约 65%，空桌面区域约 100%。粗框包含周围背景，只能用于判断采集质量，不能当作物体掩码。建议正式目标改用单独摆放、表面不反光的小盒子。

当前文件是**原始相机数据与诊断**，尚无目标掩码、桌面到相机的外参标定，也未检查真实场景的几何误差。不能把相机坐标直接写成仿真机械臂世界坐标，不能从这些帧宣称完成真实视觉抓取。下一步确定一个安全、易分割的目标物体，检查其局部深度覆盖与彩色/深度几何对应，再转换成项目 `scene.json` 输入，并做桌面标定与实际尺寸对照。

接口参考：[Orbbec 官方 Python SDK](https://github.com/orbbec/pyorbbecsdk/tree/v2-main) 与 [彩色/深度对齐示例](https://github.com/orbbec/pyorbbecsdk/blob/v2-main/examples/beginner/03_color_and_depth_aligned.py)。
